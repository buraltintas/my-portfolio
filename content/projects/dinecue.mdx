<h2>Overview</h2>
<p>
  DineCue helped people decide where to eat. It combined what the user asked
  for, their taste preferences, location, restaurant data and AI-generated
  reasoning.
</p>
<p>
  The project has been shut down, and dinecue.com now shows a shutdown notice.
  The source is public: the Next.js web app is in
  <a href="https://github.com/buraltintas/dinecue-ui">dinecue-ui</a> and the
  ASP.NET Core API in
  <a href="https://github.com/buraltintas/dinecue-api">dinecue-api</a>.
</p>

<h2>My Role</h2>
<ul>
  <li>Product idea and UX direction</li>
  <li>Frontend development</li>
  <li>Backend and API architecture</li>
  <li>Authentication flow</li>
  <li>AI and Google Places integration</li>
  <li>Deployment and production setup</li>
  <li>Domain, DNS, and email setup</li>
  <li>SEO and multilingual structure</li>
</ul>

<h2>Problem</h2>
<p>
  Choosing where to eat can be harder than it should be, especially while
  traveling or comparing unfamiliar restaurants and menus. Ratings alone do not
  tell you whether a place fits your taste, context, budget or situation.
</p>

<h2>Solution</h2>
<p>
  DineCue turned that context into personal recommendations. Users described
  what they wanted and shared a location or a restaurant&apos;s menu. Each
  suggestion came with the reasons the place fit, what to order and what to
  watch out for. There were three ways to use it: find a restaurant, scan a
  menu, or check whether a specific place fit.
</p>

<h2>Key Features</h2>
<ul>
  <li>Email OTP login</li>
  <li>Google Sign-In</li>
  <li>Personalized restaurant and dining recommendations</li>
  <li>Google Places integration</li>
  <li>AI-generated recommendation reasoning</li>
  <li>User taste and dining preferences</li>
  <li>Monthly free usage quota</li>
  <li>A Pro plan announced as coming soon</li>
  <li>Multilingual UI: Turkish, English, German</li>
  <li>SEO-friendly public pages</li>
  <li>Terms, Privacy, and About pages</li>
</ul>

<h2>Technical Highlights</h2>
<ul>
  <li>Next.js App Router frontend</li>
  <li>ASP.NET Core API backend</li>
  <li>Browser &rarr; Next.js BFF &rarr; ASP.NET Core API architecture</li>
  <li>HttpOnly cookie based auth flow</li>
  <li>Google Cloud Run deployment</li>
  <li>Custom domain: dinecue.com</li>
  <li>Resend email integration for OTP</li>
  <li>Google OAuth client integration</li>
  <li>Google Places API</li>
  <li>OpenAI API</li>
  <li>Environment-based production configuration</li>
  <li>Cloud Build continuous deployment</li>
  <li>Public source: dinecue-ui and dinecue-api</li>
</ul>

<h2>Why It Matters</h2>
<p>
  DineCue was a complete product built around one problem: decision fatigue
  when choosing food and restaurants. It brought product design, frontend UX,
  backend architecture, AI integration, authentication, cloud deployment and
  SEO together in one project.
</p>
